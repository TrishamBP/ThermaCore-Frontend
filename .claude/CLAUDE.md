# ThermaCore frontend

ThermaCore is the operator console for a data center operations intelligence platform (AMD ACT III Hackathon).
Users: data center operators and reliability engineers. They monitor thermal and workload telemetry,
inspect assets in a 3D digital twin, ask a read-only copilot, and **review** AI-generated recommendations.

The backend is a separate Python project at `../data_engineering` (FastAPI + Kafka + SQLite/PostgreSQL). It is
the source of truth. **Never modify it from this project.** Report backend gaps instead.

**Status:** implemented (2026-10-14): app shell + Overview, Live Telemetry, Digital Twin (R3F + SSE), Predictions,
Optimization (optimizer, fan-peer screening, recommendation review), AI Copilot, Alerts, System. Start Claude Code
from this `frontend/` directory, otherwise none of this configuration loads. `AGENTS.md` is generated by `next dev`.

## Non-negotiable product truths

- **All telemetry is simulated**, the twin layout is a **demonstration**. A persistent "Simulated data" indicator
  is always visible; the twin always shows the layout `notice`.
- The inlet forecaster is a `forecasting_baseline` and does **not** beat persistence. Show persistence and the skill
  score next to every prediction. Forecasts can be `UNAVAILABLE`.
- The cooling optimizer currently returns `UNAVAILABLE`. Cooling power, facility power, cooling efficiency and
  energy savings are **not measured**. `power_consumption_kw` is server IT power. Fan-energy waste is a relative
  indicator only.
- Recommendations require human review. Decisions are exactly `APPROVED_FOR_EVALUATION`, `REJECTED`, `DEFERRED`
  and **never** actuate anything. No equipment-control API exists: no "apply", "execute" or "set" buttons.
- Alerts are estimator findings persisted by an analysis run, "not a confirmed equipment fault".
- `null` means no data / not applicable. Never render it as `0`, never interpolate it into a plausible value.

Next.js (App Router) · React · TypeScript `strict` · Tailwind CSS · `@react-three/fiber` + `@react-three/drei`
(twin) · Recharts (telemetry charts) · TanStack Query (client server-state) · Zod (API boundary) · Vitest +

Choose versions at init time that are mutually compatible; nothing is installed yet. Any dependency beyond this
list needs a stated reason and user approval.

## Backend integration (verified 2026-10-14)

- Backend origin `http://127.0.0.1:8000` (never `localhost`), prefix `/api/v1`, 30 operations.
- Full catalog, states and discrepancies: [`docs/backend-contract.md`](../docs/backend-contract.md). Read it before any
  API work and re-verify the live contract (`curl http://127.0.0.1:8000/openapi.json`, real responses) first.
- Backend CORS is off (and would block `Authorization`/JSON POSTs anyway), so the browser calls a **same-origin
  proxy** route handler that forwards to `API_ORIGIN` and injects the optional server-only bearer token.
- Every error is `{error: {code, message, details}, request_id}`. Preserve `code` and `request_id` up to the UI.
- Details: `.claude/rules/api-integration.md`.

## Structure and boundaries

`src/app/(console)/<page>` (thin routes sharing the sidebar + top bar; `/` redirects to `/overview`),
`src/app/api/backend/[...path]` (the proxy), `src/features/<page>` (UI + domain logic),
`src/components/{ui,layout,charts,feedback,shared}` (domain-agnostic), `src/lib/api` (the only place that does HTTP:
`client`, `reads`, `mutations`, `schemas/`), `src/lib/{config,format,status,query-keys}`, `src/hooks` (run context,
shell queries), `src/test/fixtures` (captured backend responses).
Dependencies point inward: `app → features → components/lib`; features never import other features' internals.
Details: `.claude/rules/frontend-architecture.md`.

## Conventions (summary; rules files hold the detail)

- Components `PascalCase.tsx`, hooks `useThing.ts`, others `kebab-case.ts`; named exports; no `any`.
- Server Components by default; `"use client"` only for interactivity, charts, SSE, browser APIs, Three.js.
- Errors: normalize to `ApiError` in `lib/api/errors.ts`; render with the shared error banner (code + request ID + retry
  when safe). Never swallow errors.
- Every data view implements loading, empty, error, stale, unavailable and populated states.
- Design system: dark navy surfaces, `#FBFF12` primary text and accent, semantic status colours that never reuse the
  accent. Tokens only, no raw hex in components. `.claude/rules/styling-and-design-system.md`.
- Digital twin: backend layout drives the scene; meshes keyed by layout `id` + `asset_id`; client-only canvas.
  `.claude/rules/threejs-digital-twin.md`.

## Working rules

1. Inspect existing code and the relevant rule files before modifying anything. Prefer small, reviewable changes;
   no large rewrites or speculative abstractions.
2. Never invent endpoints, fields, enum values or capabilities. A route in documentation is not proof it works.
   Generated or hand-written types are not proof either: verify against the live backend.
3. Ask before adding a dependency (package, reason, alternatives). Use `pnpm add`.
4. Tests are mandatory for logic and states. Report only what was actually executed. No live LLM in tests.
5. Update `docs/backend-contract.md` and the relevant rule when API integration or architecture changes.
6. Never put secrets in `NEXT_PUBLIC_*`, in code, or in Claude config. Never read `.env.local`.

## Commands

```bash
# Backend (from ../data_engineering) — verified
docker compose up -d --wait kafka
uv run uvicorn app.main:app --host 127.0.0.1 --port 8000
curl http://127.0.0.1:8000/api/v1/health

# Live telemetry for the demo (new run, 20 assets, 1 simulated minute per 5 s; needs the consumer running)
uv run python -m data_engineering.streaming.producer simulate --assets 20 --continuous --duration-minutes 1440 --speedup 12 --seed 2026

# Frontend (verified)
pnpm install
pnpm dev            # http://127.0.0.1:3000
pnpm typecheck      # tsc --noEmit
pnpm lint           # eslint (flat config, eslint-config-next)
pnpm test           # vitest run (unit, contract, component; no network)
pnpm test:e2e       # playwright smoke tests against the LIVE local stack (installed Chrome; read-only)
pnpm build
pnpm screenshot overview digital-twin   # dev helper: PNGs via installed Chrome (SHOT_DIR=...)
```
